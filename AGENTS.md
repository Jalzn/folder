# Tinyfold

Minimalist personal workspace centered on projects, with documents, drawings and Kanban. Implemented and validated locally, deployed on Railway at https://folder.jalzn.com.

Read `docs/produto.md`, `docs/arquitetura.md` and the current stage in `docs/etapas/` before implementation. The local reference is `../orbis`; inspect its implementation before adapting a pattern.

## Conventions

- Code, identifiers, code comments, commits and PRs: English.
- UI and documentation: Brazilian Portuguese. Use Portuguese URLs and English module names.
- Use the single root `package.json` for dependencies, scripts and exact `#` imports. The folders `core`, `auth`, `rich-text`, `projects`, `documents`, `drawings`, `board`, `workspace`, `server` and `web` remain architectural boundaries, not separate pnpm packages. Keep TypeScript configurations at the root, separated by Node, browser and E2E environment.
- Business modules use `domain/`, `application/` and `infra/`, with explicit public exports.
- Domain rules and `rich-text` are pure. Application code depends on local ports, not SQL, HTTP or React. Business modules never import each other, including type-only imports; the server connects their ports through public entries.
- Runtime business classes extend the class generated by a private `defineModule` definition and expose only `id`, `commands`, `queries` and subscription-only `events`. The `#<module>/composition` entries are restricted to the owning module and server, including integrated tests; scripts reuse server composition.
- `project.ts` defines the software project and application recipes with `defineProject`. `defineApplication` creates isolated module/service maps when explicitly called; definitions perform no I/O. Business modules, web and E2E never import `#project`, including types. The host drains accepted HTTP/MCP work before the application's synchronous, idempotent disposal and closes its own database afterwards.
- Historical migration registrations use `MigrationModuleDefinition`/`defineMigrationModule`; keep them separate from runtime `ModuleDefinition` and preserve their existing IDs and checksums.
- Each module writes only its owned tables. Workspace coordinates through scoped participants and has explicit read-only aggregate SQL adapters. A coordinated write uses one unit of work and one legacy idempotency record; participants never escape the transaction. Events publish after commit and never implement atomic business rules.
- Keep all persisted data on server-side SQLite. Use the Orbis account/password/session pattern.
- Document edits must preserve drafts, detect stale versions and allow safe retries.
- Applied migrations are immutable; append a new migration to change the database.
- Adapt Orbis SQL, migrations, locking, backups and request-size limits for Tinyfold. Inspect these explicitly when reusing code.
- Use the approved Sumário visual direction in `docs/identidade-visual.md`. The next interface is specified in `docs/interface/`.
- Requested design explorations go through `claude-infinity-0` and Claude's native artifact system, with its returned artifact URL. The current reference is in `docs/identidade-visual.md`.
- Keep documentation consistent with implemented behavior and distinguish planned checks from executed checks.
- Database tests use isolated temporary SQLite files. Restore checks never overwrite the main database.

Use the pinned tools with `mise exec -- pnpm <command>`. `check` runs lint, types, dependency boundaries and unit tests. Run `test:db` for temporary SQLite databases; run `build` before `e2e` for Google Chrome desktop/mobile tests. E2E specs import `test` from `e2e/fixtures.ts` for an automatic fresh project; use `isolatedTest` for sample/custom setup: four workers each own a server, an available port and a temporary SQLite file; `@timing` runs afterwards in one worker. Use `.desktop.spec.ts` or `.mobile.spec.ts` for device-specific files and `@desktop`/`@mobile` for individual cases. `e2e:smoke` runs the short desktop/mobile subset. `e2e:visual` compares machine-local references selected by `VISUAL_BASELINE_DIR`; capture them on the baseline commit and only update reviewed, approved differences. Manual browser validation uses the Chrome session inside Herdr's Content Viewer (`herdr-preview`); read the personal Herdr guide at `/Users/standard/.agent-switch/docs/herdr-workspace.md`. `dev` starts the UI on localhost:5170. See `docs/implantacao.md` for setup and backup commands, and `docs/validacao.md` for executed checks.
